Control plane · exit condition

Refuses to deliver anything it cannot prove.

runmill is the control plane and exit condition for autonomous software engineering.

Your coding-agent harness already has a loop. runmill is what makes that loop safe to leave running: deterministic selection and an atomic claim from the backlog, proven isolation, evidence that the tests you actually cared about ran against the exact candidate, fresh-context review, and a merge gate that fails closed.

Try it in 60 seconds Read the coverage contract
runmill daemon 
$ runmill daemon   ENG-102  →  PR_DELIVERED   $0.02  ENG-101  →  PR_DELIVERED   $0.02  ENG-118  →  NEEDS_HUMAN    $0.03              check "unit" exited 0 having discovered no tests   stopped: breaker  1 run could not be verified

The third run exited 0. It still failed. A suite that discovers no tests is the most convincing false green there is, because it looks identical to a full pass.

Isn't this just a loop?

The loop is three lines, and it genuinely works when an oracle already exists. A flaky test is its own judge. A nightly end-to-end suite is its own judge. If that describes your problem, use the three lines. You don't need this. 

while :; do cat PROMPT.md | claude-code; done

It stops working when nothing outside the model can tell you the work is finished. Then the exit condition quietly becomes the model's own opinion, and "the agent said it was done" is a different claim from "it is done" in exactly the cases you care about.

Harnesses get agents running. runmill is the layer that decides whether what came out is allowed to land.

Why this layer, and why now

The conversation moved in three steps, and each one settled before the next began.

  1. Harness
    Settled: 2025 to early 2026 Everything around the model. Sandbox, tools, permissions, context, tests, review gates, and the inner execution loop. Claude Code and Codex are the canonical examples. The model became the commodity and the harness became the engineering surface, because a harness buys observability, constraint, and checkability rather than correctness.
  2. Loop
    The current frontier Once the harness is reliable, the outer loop has to decide when to stop. Triggers, goals, durable state, and a verifier. The first four are the easy ones. The verifier is the whole problem, and without it the exit condition collapses into the model's own opinion.
  3. Control plane
    The governance layer, being defined now Sits above and across harnesses: identity, policy enforcement, budgets and circuit breakers, kill switches, audit trails, and deterministic governance of side effects. Every team that has run agents continuously has ended up building one, because the harness alone never had the authority to say no.

180% more code generated, 30% more shipped

MIT research on agent-assisted development. The gap between those two numbers is the verification bottleneck, and it is the only thing runmill is built to close. Merge gates that were tolerable compromises at human volume become liabilities at agent volume.

What a harness does

Gets an agent running. Gives it tools, a sandbox, context, and an inner loop. Claude Code and Codex are very good at this, and runmill does not compete with them.

What a control plane does

Keeps agents under control across harnesses. Owns the claim, the budget, the audit trail, and every side effect. Decides whether the work is allowed to land.

Seven gates, evaluated in order

Any failure ends the run in a terminal state that names which gate and why. runmill policy explain <run-id> prints this for any run.

  1. 01
    The lease is still heldA compare-and-swap on a git ref, checked against a fencing generation before every external mutation.
  2. 02
    Checks discovered, executed, fresh, unskippedRun against the exact candidate commit in a clean detached worktree, with the tree hashed either side.
  3. 03
    Review verdict, cross-checkedA clean report on a diff touching risk-escalating paths escalates rather than being believed.
  4. 04
    Branch protection is readableUnreadable rules are unknown, not absent. A permissions error is not permission.
  5. 05
    Every required context reportedNeutral and skipped are not coverage. A context that never gets scheduled fails rather than waits.
  6. 06
    The credential provably cannot edit protectionIf it could rewrite the rules, "no merge bypassed protection" is not a verifiable claim.
  7. 07
    Autonomy mode permits the classified riskChanges touching declared risk paths escalate instead of auto-merging.

Autonomy you turn up on evidence

Start where a mistake costs a review comment. The built-in evaluation harness replays a suite built from your own history, reporting pass rates with confidence intervals and refusal accuracy on its own line, so moving up a rung is a decision you can defend.

observe

Selects and plans. No lease, no clone, no repository mutation.

pr-onlyDefault

Implements, verifies, reviews, fixes, opens a pull request. Never merges.

guarded-merge

May merge low-risk changes once every automated and repository gate passes.

continuous

Repeats guarded execution until work runs out, a budget is reached, or a breaker opens.

Thin enough to audit

runmill reads your entire repository, holds a backlog credential and a forge token, and can merge to your default branch. A security model is a claim, so the surface is kept small enough that you can check it rather than take it on faith.

Isolation is the OS, not a library

bubblewrap on Linux, Seatbelt on macOS. doctor does not ask whether a sandbox exists: it plants a secret, tries to read it from inside, and fails if that succeeds.

Coordination is git

The lease is a ref pushed to origin, so mutual exclusion comes from a server-side atomic create. No lock service to operate.
