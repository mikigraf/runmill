What Runmill owns

The delivery process around the agent.

The agent writes and reviews code. Runmill handles selection, claims, workspaces, required checks, pull requests, CI state, and merge policy. Missing evidence stops the run for a person.

01 / CLAIM

One issue, one worker

Durable leases keep two workers from taking the same issue. A stale worker loses authority before it can mutate external state.

02 / ISOLATE

A workspace with a hard edge

Each task runs in its own sandboxed workspace. Runmill verifies the host boundary before an agent starts.

03 / PROVE

Checks tied to the candidate

Required checks run against the exact commit in a clean checkout. A green command with missing coverage does not count.

04 / GATE

Fresh review, deterministic delivery

The reviewer gets fresh context. Runmill, rather than the model, owns pushes, pull requests, backlog changes, and merge decisions.

Zero credentials

See one complete run.

The bundled demo uses temporary storage and simulated integrations. It exercises the orchestration and Git verification path without touching your repository.

# install the source preview
$ git clone https://github.com/mikigraf/runmill.git
$ cd runmill && npm ci
$ npm run build && npm link

# run the delivery loop in a temp workspace
$ runmill demo

Maturity

Start in pr-only.

Runmill is a developer preview. The recommended mode opens reviewed pull requests and leaves merging to a person. Automatic merge modes are experimental and need explicit evaluation against your repositories and protection rules.
